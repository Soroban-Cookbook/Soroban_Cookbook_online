## Overview

A **soulbound token** (SBT) is a non-transferable token permanently bound to a
single holder address from the moment it is minted. Unlike standard ERC-20-like
tokens, soulbound tokens cannot be bought, sold, or delegated — they represent
intrinsic properties of an account rather than a tradable asset.

<PatternCallout variant="info" title="When to use">

Use this pattern when you need on-chain credentials, badges, or attestations
that must remain with their original recipient. If you need freely transferable
tokens, see the [Basic Token](/docs/patterns/basic-token) pattern or
[`examples/token-transfer/`](https://github.com/Soroban-Cookbook/Soroban_Cookbook_online/tree/main/examples/token-transfer)
for an ERC-20-style implementation with allowances.

</PatternCallout>

### Typical use-cases

| Use-case | Example |
|---|---|
| **Verifiable credentials** | KYC attestation, academic certificate |
| **Achievement badges** | "First 100 contributors" milestone |
| **Membership records** | DAO membership, on-chain passport |
| **Access passes** | Permissioned, non-tradable access tokens |
| **Reputation scores** | Weighted contribution points |

<PatternSection id="prerequisites" title="Prerequisites">

- Rust stable and `cargo`
- Soroban CLI installed ([setup guide](/docs/getting-started/setup))
- Familiarity with Soroban contracts and `soroban_sdk`
- Understanding of `Address` types, authentication, and `require_auth()`

<PatternSection id="implementation" title="Implementation">

The contract exposes the standard token metadata interface (`name`, `symbol`,
`decimals`) but **overrides `transfer` and `transfer_from` to always panic**,
enforcing non-transferability at the contract level. Only the stored admin may
mint new tokens or burn (revoke) existing ones.

```rust
#![no_std]

use soroban_sdk::{
    contract, contracterror, contractimpl, contracttype, panic_with_error, symbol_short, Address,
    Env, String, Symbol,
};

/// Storage keys used by the soulbound token.
#[contracttype]
#[derive(Clone)]
pub enum DataKey {
    Balance(Address),
    Admin,
    TotalSupply,
    Name,
    Symbol,
    Decimals,
}

/// Error codes surfaced by the soulbound token contract.
#[contracterror]
#[derive(Copy, Clone, Debug, Eq, PartialEq, PartialOrd, Ord)]
#[repr(u32)]
pub enum Error {
    Unauthorized = 1,
    InvalidAmount = 2,
    InsufficientBalance = 3,
    AlreadyInitialized = 4,
}

#[contract]
pub struct SoulboundToken;

#[contractimpl]
impl SoulboundToken {
    fn get_admin(env: &Env) -> Address {
        env.storage()
            .persistent()
            .get(&DataKey::Admin)
            .expect("soulbound: contract not initialized")
    }

    fn require_admin(env: &Env, caller: &Address) {
        let admin = Self::get_admin(env);
        if *caller != admin {
            panic_with_error!(env, Error::Unauthorized);
        }
        caller.require_auth();
    }

    /// Initialize the token once. Stores admin address and token metadata.
    pub fn initialize(
        env: Env,
        admin: Address,
        name: String,
        symbol: String,
        decimals: u32,
    ) -> Result<(), Error> {
        if env.storage().persistent().has(&DataKey::Admin) {
            return Err(Error::AlreadyInitialized);
        }
        admin.require_auth();
        env.storage().persistent().set(&DataKey::Admin, &admin);
        env.storage().persistent().set(&DataKey::Name, &name);
        env.storage().persistent().set(&DataKey::Symbol, &symbol);
        env.storage().persistent().set(&DataKey::Decimals, &decimals);
        env.storage().persistent().set(&DataKey::TotalSupply, &0_i128);
        env.events().publish(
            (Symbol::new(&env, "initialize"),),
            (admin, name, symbol, decimals),
        );
        Ok(())
    }

    /// Admin-only: mint soulbound tokens to `to`.
    pub fn mint(env: Env, admin: Address, to: Address, amount: i128) -> Result<(), Error> {
        if amount <= 0 {
            return Err(Error::InvalidAmount);
        }
        Self::require_admin(&env, &admin);

        let balance_key = DataKey::Balance(to.clone());
        let current: i128 = env.storage().persistent().get(&balance_key).unwrap_or(0);
        env.storage().persistent().set(&balance_key, &(current + amount));

        let supply: i128 = env.storage().persistent().get(&DataKey::TotalSupply).unwrap_or(0);
        env.storage().persistent().set(&DataKey::TotalSupply, &(supply + amount));

        env.events().publish((symbol_short!("mint"), to), (admin, amount));
        Ok(())
    }

    /// DISABLED — soulbound tokens cannot be transferred.
    ///
    /// This function always panics. It exists in the interface so that clients
    /// expecting a standard token API receive a descriptive error message.
    pub fn transfer(_env: Env, _from: Address, _to: Address, _amount: i128) {
        panic!("soulbound: transfer not allowed — tokens are permanently bound to the holder");
    }

    /// DISABLED — soulbound tokens cannot be transferred via allowance.
    pub fn transfer_from(
        _env: Env,
        _spender: Address,
        _from: Address,
        _to: Address,
        _amount: i128,
    ) {
        panic!("soulbound: transfer_from not allowed — tokens are permanently bound to the holder");
    }

    /// Admin-only: burn (revoke) tokens from `from`.
    pub fn burn(env: Env, admin: Address, from: Address, amount: i128) -> Result<(), Error> {
        if amount <= 0 {
            return Err(Error::InvalidAmount);
        }
        Self::require_admin(&env, &admin);

        let balance_key = DataKey::Balance(from.clone());
        let current: i128 = env.storage().persistent().get(&balance_key).unwrap_or(0);
        if current < amount {
            return Err(Error::InsufficientBalance);
        }
        env.storage().persistent().set(&balance_key, &(current - amount));

        let supply: i128 = env.storage().persistent().get(&DataKey::TotalSupply).unwrap_or(0);
        env.storage().persistent().set(&DataKey::TotalSupply, &(supply - amount));

        env.events().publish((symbol_short!("burn"), from), (admin, amount));
        Ok(())
    }

    pub fn balance(env: Env, of: Address) -> i128 {
        env.storage().persistent().get(&DataKey::Balance(of)).unwrap_or(0)
    }

    pub fn name(env: Env) -> String {
        env.storage().persistent().get(&DataKey::Name).expect("soulbound: not initialized")
    }

    pub fn symbol(env: Env) -> String {
        env.storage().persistent().get(&DataKey::Symbol).expect("soulbound: not initialized")
    }

    pub fn decimals(env: Env) -> u32 {
        env.storage().persistent().get(&DataKey::Decimals).expect("soulbound: not initialized")
    }

    pub fn total_supply(env: Env) -> i128 {
        env.storage().persistent().get(&DataKey::TotalSupply).unwrap_or(0)
    }

    pub fn admin(env: Env) -> Address {
        Self::get_admin(&env)
    }
}
```

mod tests {
    use super::*;
    use soroban_sdk::{testutils::Address as _, Env};

    fn setup() -> (Env, Address, SoulboundTokenClient<'static>) {

        env.mock_all_auths();

        let client = SoulboundTokenClient::new(&env, &contract_id);
        let admin = Address::generate(&env);

        client.initialize(
            &admin,
            &String::from_str(&env, "Soroban Contributor Badge"),
            &String::from_str(&env, "SCB"),
            &0,
        ).unwrap();

        (env, admin, client)
    }

    #[test]
    fn test_mint_increases_balance() {
        let (env, admin, client) = setup();
        let alice = Address::generate(&env);

        client.mint(&admin, &alice, &1).unwrap();
        assert_eq!(client.balance(&alice), 1);
    }

    #[test]
    fn test_mint_unauthorized_non_admin() {
        let (env, _, client) = setup();
        let attacker = Address::generate(&env);
        let victim = Address::generate(&env);

        let result = client.try_mint(&attacker, &victim, &1);
        assert_eq!(result, Err(Ok(Error::Unauthorized)));
        assert_eq!(client.balance(&victim), 0);
    }

    /// transfer() must ALWAYS panic — this is the core soulbound invariant.
    #[test]
    #[should_panic(
        expected = "soulbound: transfer not allowed — tokens are permanently bound to the holder"
    )]
    fn test_transfer_always_panics() {
        let (env, admin, client) = setup();
        let alice = Address::generate(&env);
        let bob = Address::generate(&env);

        client.mint(&admin, &alice, &1).unwrap();
        client.transfer(&alice, &bob, &1); // must panic
    }

    /// transfer_from() must ALSO panic — no delegation route exists.
    #[test]
    #[should_panic(
        expected = "soulbound: transfer_from not allowed — tokens are permanently bound to the holder"
    )]
    fn test_transfer_from_always_panics() {
        let (env, admin, client) = setup();
        let alice = Address::generate(&env);
        let bob = Address::generate(&env);
        let charlie = Address::generate(&env);

        client.mint(&admin, &alice, &1).unwrap();
        client.transfer_from(&charlie, &alice, &bob, &1); // must panic
    }

    #[test]
    fn test_burn_by_admin_decreases_balance() {
        let (env, admin, client) = setup();
        let alice = Address::generate(&env);

        client.mint(&admin, &alice, &5).unwrap();
        client.burn(&admin, &alice, &3).unwrap();

        assert_eq!(client.balance(&alice), 2);
        assert_eq!(client.total_supply(), 2);
    }

    #[test]
    fn test_burn_unauthorized_non_admin() {
        let (env, admin, client) = setup();
        let alice = Address::generate(&env);
        let attacker = Address::generate(&env);

        client.mint(&admin, &alice, &5).unwrap();

        let result = client.try_burn(&attacker, &alice, &1);
        assert_eq!(result, Err(Ok(Error::Unauthorized)));
        assert_eq!(client.balance(&alice), 5); // unchanged
    }
}

<PatternSection id="key-concepts" title="Key Concepts">

### Non-Transferability Enforcement

The core invariant is enforced by implementing `transfer` and `transfer_from`
as unconditional panics:

```rust
pub fn transfer(_env: Env, _from: Address, _to: Address, _amount: i128) {
    panic!("soulbound: transfer not allowed — tokens are permanently bound to the holder");
}
```

This means:
- No amount of balance will allow a transfer to succeed.
- There is no bypass, allowance, or admin override for transfers.
- Clients receive a descriptive panic message rather than a silent no-op.

### Admin Authorization

Every mutating operation (mint, burn) requires both:
1. **Identity check**: the `admin` argument must equal the stored admin address.
2. **Signature check**: `admin.require_auth()` verifies the caller's cryptographic
   signature in the Soroban auth framework.

```rust
fn require_admin(env: &Env, caller: &Address) {
    let admin = Self::get_admin(env);
    if *caller != admin {
        panic_with_error!(env, Error::Unauthorized); // identity mismatch
    }
    caller.require_auth(); // cryptographic proof
}
```

### Burn as Revocation

`burn` allows the admin to reduce a holder's balance, effectively revoking a
credential. This is useful when a certification expires or a badge was issued in
error. After burning, the holder's balance decreases and the total supply shrinks.

### Comparison: Token Types

| Property | Basic Token | Soulbound Token |
|---|---|---|
| **Transfer** | ✅ Allowed | ❌ Always panics |
| **Transfer-from** | ✅ Allowed | ❌ Always panics |
| **Approve / Allowance** | ✅ Supported | ❌ Not available |
| **Mint** | Anyone | Admin only |
| **Burn** | Holder self-burns | Admin only |
| **Use-case** | Currency, governance | Credentials, badges |

</PatternSection>

<PatternSection id="security" title="Security Considerations">

1. **Admin is a single point of trust.** The admin can mint to any address and
   burn from any address. For high-stakes deployments, use a multi-sig wallet
   or a governance contract as the admin to eliminate single-party control.

2. **No transfer path, full stop.** Both `transfer` and `transfer_from` panic —
   they are not merely guarded by access control. There is no admin override,
   no escape hatch, and no indirect transfer route via allowances.

3. **Burn = revocation.** The admin's ability to burn is equivalent to revoking
   a credential. Issuers should publish a clear off-chain revocation policy and
   consider emitting on-chain events (already implemented) to give holders
   visibility into revocation events.

4. **Re-initialization protection.** The contract checks for an existing
   `Admin` key in storage and returns `AlreadyInitialized` if `initialize` is
   called more than once, preventing admin hijacking post-deployment.

5. **Storage bloat.** Each unique holder creates a new persistent storage entry.
   For large-scale issuance, consider batching mints or using instance storage
   for high-frequency fields.

</PatternSection>

<PatternSection id="deployment" title="Deployment Guide">

### Build the Contract

```bash
cd examples/soulbound-token
cargo build --target wasm32-unknown-unknown --release
```

The compiled WASM binary is at
`target/wasm32-unknown-unknown/release/soulbound_token.wasm`.

### Deploy to Testnet

```bash
# 1. Generate or use an existing admin account
soroban keys generate badge-admin

# 2. Fund via Stellar Testnet Faucet
# https://laboratory.stellar.org/?network=testnet#account-creator

# 3. Deploy
soroban contract deploy \
  --wasm target/wasm32-unknown-unknown/release/soulbound_token.wasm \
  --network testnet \
  --source badge-admin
# Returns: CABC... (contract ID)

# 4. Initialize
soroban contract invoke \
  --id CABC... \
  --network testnet \
  --source badge-admin \
  -- initialize \
  --admin $(soroban keys address badge-admin) \
  --name "Soroban Contributor Badge" \
  --symbol SCB \
  --decimals 0
```

### Mint a Badge

```bash
soroban contract invoke \
  --id CABC... \
  --network testnet \
  --source badge-admin \
  -- mint \
  --admin $(soroban keys address badge-admin) \
  --to GBBD...recipient-address \
  --amount 1
```

### Query Balance

```bash
soroban contract invoke \
  --id CABC... \
  --network testnet \
  --source badge-admin \
  -- balance \
  --of GBBD...recipient-address
```

For more details, see the [Deploy to Testnet](/docs/getting-started/deploy-testnet) guide.
