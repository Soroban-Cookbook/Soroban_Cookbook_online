## Overview

This page demonstrates the **pattern detail template**: metadata header, prerequisite and security sections, tabbed code, and related patterns. Use it as a starting point when adding new contract patterns to the cookbook.

The snippets below match [`examples/hello-world/src/lib.rs`](https://github.com/Soroban-Cookbook/Soroban_Cookbook_online/blob/main/examples/hello-world/src/lib.rs). `HelloWorld` reads and writes instance storage key `"msg"` via `hello()` and `set_message()`. There is no `hello(to: String)` entry point.

<PatternSection id="prerequisites" title="Prerequisites">

- Rust stable and `cargo` ([setup guide](/docs/getting-started/setup))
- Stellar CLI installed (`stellar --version`) — see [Building and Compilation](/docs/getting-started/building-and-compilation)
- `wasm32-unknown-unknown` target (`rustup target list --installed`)
- Basic familiarity with Rust modules and `soroban_sdk` types

</PatternSection>

<PatternSection id="implementation" title="Implementation">

Read instance storage and return a greeting string. This is the smallest useful contract for bootstrapping tests and deployments. Canonical source: [`examples/hello-world/src/lib.rs`](https://github.com/Soroban-Cookbook/Soroban_Cookbook_online/blob/main/examples/hello-world/src/lib.rs) (tests are in the same file under `#[cfg(test)]`, not a separate `src/test.rs`).

<PatternCallout variant="info" title="When to use">

Use this pattern to verify tooling, ledger integration, and storage before layering tokens or authorization.

</PatternCallout>

use soroban_sdk::{contract, contractimpl, Env, String};

#[contract]
pub struct HelloWorld;

#[contractimpl]
impl HelloWorld {
    /// Return a greeting stored in instance storage, or a default greeting.
    pub fn hello(env: Env) -> String {
        env.storage()
            .instance()
            .get(&"msg")
            .unwrap_or(String::from_str(&env, "Hello, Soroban!"))
    }

    /// Store a custom greeting message.
    pub fn set_message(env: Env, message: String) {
        env.storage().instance().set(&"msg", &message);
    }
}`,

<PatternSection id="security" title="Security considerations">

- **Storage scope**: Instance storage is shared across all invocations; never store per-user secrets without namespacing by `Address`.
- **Upgrade surface**: If you add admin functions later, protect them with `require_auth` and explicit roles.
- **Re-entrancy**: Not applicable to this minimal example; review when adding cross-contract calls.

<PatternCallout variant="warning" title="Production checklist">

Before mainnet, add thorough tests, metering review, and an explicit data migration plan if storage layout changes.

</PatternCallout>
