Soulbound Token

intermediate
Category
Token
Pattern ID
soulbound-token
Status
stable
Last reviewed
August 2026

Overview​

A soulbound token (SBT) is a non-transferable token permanently bound to a single holder address from the moment it is minted. Unlike standard ERC-20-like tokens, soulbound tokens cannot be bought, sold, or delegated — they represent intrinsic properties of an account rather than a tradable asset.

When to use

Use this pattern when you need on-chain credentials, badges, or attestations that must remain with their original recipient. If you need freely transferable tokens, see the Basic Token pattern or examples/token-transfer/ for an ERC-20-style implementation with allowances.

Typical use-cases​

Use-caseExample
Verifiable credentialsKYC attestation, academic certificate
Achievement badges"First 100 contributors" milestone
Membership recordsDAO membership, on-chain passport
Access passesPermissioned, non-tradable access tokens
Reputation scoresWeighted contribution points

Prerequisites

  • Rust stable and cargo
  • Soroban CLI installed (setup guide)
  • Familiarity with Soroban contracts and soroban_sdk
  • Understanding of Address types, authentication, and require_auth()

Implementation

The contract exposes the standard token metadata interface (name, symbol, decimals) but overrides transfer and transfer_from to always fail with the TransferNotAllowed contract error, enforcing non-transferability at the contract level. Only the stored admin may mint new tokens or burn (revoke) existing ones.

⚠️ Disclaimer: Un-audited Example

This contract is provided for educational purposes only and has not been audited. Do NOT use in production or with real funds.

  • No reentrancy concerns apply – the contract does not expose any mutable entry points that could be re‑entered.
  • Storage entries persist indefinitely; there is no automatic TTL or data‑expiry mechanism.

#![no_std]

use soroban_sdk::{
    contract, contracterror, contractimpl, contracttype, panic_with_error, symbol_short, Address,
    Env, String, Symbol,
};

/// Storage keys used by the soulbound token.
#[contracttype]
#[derive(Clone)]
pub enum DataKey {
    Balance(Address),
    Admin,
    TotalSupply,
    Name,
    Symbol,
    Decimals,
}

/// Error codes surfaced by the soulbound token contract.
#[contracterror]
#[derive(Copy, Clone, Debug, Eq, PartialEq, PartialOrd, Ord)]
#[repr(u32)]
pub enum Error {
    Unauthorized = 1,
    InvalidAmount = 2,
    InsufficientBalance = 3,
    AlreadyInitialized = 4,
    TransferNotAllowed = 5,
}

#[contract]
pub struct SoulboundToken;

#[contractimpl]
impl SoulboundToken {
    fn get_admin(env: &Env) -> Address {
        env.storage()
            .persistent()
            .get(&DataKey::Admin)
            .expect("soulbound: contract not initialized")
    }

    fn require_admin(env: &Env, caller: &Address) {
        let admin = Self::get_admin(env);
        if *caller != admin {
            panic_with_error!(env, Error::Unauthorized);
        }
        caller.require_auth();
    }

    /// Initialize the token once. Stores admin address and token metadata.
    pub fn initialize(
        env: Env,
        admin: Address,
        name: String,
        symbol: String,
        decimals: u32,
    ) -> Result<(), Error> {
        if env.storage().persistent().has(&DataKey::Admin) {
            return Err(Error::AlreadyInitialized);
        }
        admin.require_auth();
        env.storage().persistent().set(&DataKey::Admin, &admin);
        env.storage().persistent().set(&DataKey::Name, &name);
        env.storage().persistent().set(&DataKey::Symbol, &symbol);
        env.storage().persistent().set(&DataKey::Decimals, &decimals);
        env.storage().persistent().set(&DataKey::TotalSupply, &0_i128);
        env.events().publish(
            (Symbol::new(&env, "initialize"),),
            (admin, name, symbol, decimals),
        );
        Ok(())
    }

    /// Admin-only: mint soulbound tokens to `to`.
    pub fn mint(env: Env, admin: Address, to: Address, amount: i128) -> Result<(), Error> {
        if amount <= 0 {
            return Err(Error::InvalidAmount);
        }
        Self::require_admin(&env, &admin);

        let balance_key = DataKey::Balance(to.clone());
        let current: i128 = env.storage().persistent().get(&balance_key).unwrap_or(0);
        env.storage().persistent().set(&balance_key, &(current + amount));

        let supply: i128 = env.storage().persistent().get(&DataKey::TotalSupply).unwrap_or(0);
        env.storage().persistent().set(&DataKey::TotalSupply, &(supply + amount));

        env.events().publish((symbol_short!("mint"), to), (admin, amount));
        Ok(())
    }

    /// DISABLED — soulbound tokens cannot be transferred.
    ///
    /// The call always fails with `Error::TransferNotAllowed`. It exists in the
    /// interface so that clients expecting a standard token API receive a
    /// descriptive contract error.
    pub fn transfer(_env: Env, _from: Address, _to: Address, _amount: i128) -> Result<(), Error> {
        Err(Error::TransferNotAllowed)
    }

    /// DISABLED — soulbound tokens cannot be transferred via allowance.
    pub fn transfer_from(
        _env: Env,
        _spender: Address,
        _from: Address,
        _to: Address,
        _amount: i128,
    ) -> Result<(), Error> {
        Err(Error::TransferNotAllowed)
    }

    /// Admin-only: burn (revoke) tokens from `from`.
    pub fn burn(env: Env, admin: Address, from: Address, amount: i128) -> Result<(), Error> {
        if amount <= 0 {
            return Err(Error::InvalidAmount);
        }
        Self::require_admin(&env, &admin);

        let balance_key = DataKey::Balance(from.clone());
        let current: i128 = env.storage().persistent().get(&balance_key).unwrap_or(0);
        if current < amount {
            return Err(Error::InsufficientBalance);
        }
        env.storage().persistent().set(&balance_key, &(current - amount));

        let supply: i128 = env.storage().persistent().get(&DataKey::TotalSupply).unwrap_or(0);
        env.storage().persistent().set(&DataKey::TotalSupply, &(supply - amount));

        env.events().publish((symbol_short!("burn"), from), (admin, amount));
        Ok(())
    }

    pub fn balance(env: Env, of: Address) -> i128 {
        env.storage().persistent().get(&DataKey::Balance(of)).unwrap_or(0)
    }

    pub fn name(env: Env) -> String {
        env.storage().persistent().get(&DataKey::Name).expect("soulbound: not initialized")
    }

    pub fn symbol(env: Env) -> String {
        env.storage().persistent().get(&DataKey::Symbol).expect("soulbound: not initialized")
    }

    pub fn decimals(env: Env) -> u32 {
        env.storage().persistent().get(&DataKey::Decimals).expect("soulbound: not initialized")
    }

    pub fn total_supply(env: Env) -> i128 {
        env.storage().persistent().get(&DataKey::TotalSupply).unwrap_or(0)
    }

    pub fn admin(env: Env) -> Address {
        Self::get_admin(&env)
    }
}
#[cfg(test)]
mod tests {
    use super::*;
    use soroban_sdk::{
        symbol_short,
        testutils::{
            Address as _, AuthorizedFunction, AuthorizedInvocation, MockAuth, MockAuthInvoke,
        },
        Env, IntoVal, Val, Vec,
    };

    fn setup() -> (Env, Address, SoulboundTokenClient<'static>) {
        let env = Env::default();
        env.mock_all_auths();
        let contract_id = env.register(SoulboundToken, ());
        let client = SoulboundTokenClient::new(&env, &contract_id);
        let admin = Address::generate(&env);

        client.initialize(
            &admin,
            &String::from_str(&env, "Soroban Contributor Badge"),
            &String::from_str(&env, "SCB"),
            &0,
        );

        (env, admin, client)
    }

    /// Authorize `admin` for exactly one contract entrypoint.
    fn mock_admin_auth(
        env: &Env,
        contract_id: &Address,
        admin: &Address,
        fn_name: &str,
        args: Vec<Val>,
    ) {
        env.mock_auths(&[MockAuth {
            address: admin,
            invoke: &MockAuthInvoke {
                contract: contract_id,
                fn_name,
                args,
                sub_invokes: &[],
            },
        }]);
    }

    #[test]
    fn test_mint_increases_balance() {
        let (env, admin, client) = setup();
        let alice = Address::generate(&env);

        client.mint(&admin, &alice, &1);
        assert_eq!(client.balance(&alice), 1);
    }

    #[test]
    fn test_mint_unauthorized_non_admin() {
        let (env, _, client) = setup();
        let attacker = Address::generate(&env);
        let victim = Address::generate(&env);

        let result = client.try_mint(&attacker, &victim, &1);
        assert_eq!(result, Err(Ok(Error::Unauthorized)));
        assert_eq!(client.balance(&victim), 0);
    }

    /// transfer() must ALWAYS fail with the soulbound contract error — this is
    /// the core soulbound invariant. The result is captured and matched
    /// against the exact error, so the test fails if transfer ever succeeds.
    #[test]
    fn test_transfer_fails_with_contract_error() {
        let (env, admin, client) = setup();
        let alice = Address::generate(&env);
        let bob = Address::generate(&env);

        // Minting is admin-gated: authorize the admin for this call only.
        mock_admin_auth(
            &env,
            &client.address,
            &admin,
            "mint",
            (admin.clone(), alice.clone(), 1i128).into_val(&env),
        );
        client.mint(&admin, &alice, &1);

        // The admin's authorization was genuinely required by `mint`.
        assert_eq!(
            env.auths(),
            [(
                admin.clone(),
                AuthorizedInvocation {
                    function: AuthorizedFunction::Contract((
                        client.address.clone(),
                        symbol_short!("mint"),
                        (admin.clone(), alice.clone(), 1i128).into_val(&env),
                    )),
                    sub_invocations: [].into(),
                },
            )]
        );

        // The transfer must be rejected with the soulbound contract error.
        let result = client.try_transfer(&alice, &bob, &1);
        assert_eq!(result, Err(Ok(Error::TransferNotAllowed)));

        // The rejected transfer must not have moved any balance.
        assert_eq!(client.balance(&alice), 1);
        assert_eq!(client.balance(&bob), 0);
        assert_eq!(client.total_supply(), 1);
    }

    /// transfer_from() must ALSO fail — no delegation route exists.
    #[test]
    fn test_transfer_from_fails_with_contract_error() {
        let (env, admin, client) = setup();
        let alice = Address::generate(&env);
        let bob = Address::generate(&env);
        let charlie = Address::generate(&env);

        client.mint(&admin, &alice, &1);

        let result = client.try_transfer_from(&charlie, &alice, &bob, &1);
        assert_eq!(result, Err(Ok(Error::TransferNotAllowed)));

        assert_eq!(client.balance(&alice), 1);
        assert_eq!(client.balance(&bob), 0);
    }

    #[test]
    fn test_burn_by_admin_decreases_balance() {
        let (env, admin, client) = setup();
        let alice = Address::generate(&env);

        client.mint(&admin, &alice, &5);
        client.burn(&admin, &alice, &3);

        assert_eq!(client.balance(&alice), 2);
        assert_eq!(client.total_supply(), 2);
    }

    #[test]
    fn test_burn_unauthorized_non_admin() {
        let (env, admin, client) = setup();
        let alice = Address::generate(&env);
        let attacker = Address::generate(&env);

        client.mint(&admin, &alice, &5);

        let result = client.try_burn(&attacker, &alice, &1);
        assert_eq!(result, Err(Ok(Error::Unauthorized)));
        assert_eq!(client.balance(&alice), 5); // unchanged
    }
}
# Run tests for this specific crate
cargo test --package soulbound-token

# Run with output for debugging
cargo test --package soulbound-token -- --nocapture

Expected output: all tests pass, including the transfer tests that assert the TransferNotAllowed contract error.

Key Concepts

Non-Transferability Enforcement​

The core invariant is enforced by implementing transfer and transfer_from as unconditional rejections:

pub fn transfer(_env: Env, _from: Address, _to: Address, _amount: i128) -> Result<(), Error> {
    Err(Error::TransferNotAllowed)
}

This means:

  • No amount of balance will allow a transfer to succeed.
  • There is no bypass, allowance, or admin override for transfers.
  • Clients receive a descriptive contract error rather than a silent no-op.

Admin Authorization​

Every mutating operation (mint, burn) requires both:

  1. Identity check: the admin argument must equal the stored admin address.
  2. Signature check: admin.require_auth() verifies the caller's cryptographic signature in the Soroban auth framework.
fn require_admin(env: &Env, caller: &Address) {
    let admin = Self::get_admin(env);
    if *caller != admin {
        panic_with_error!(env, Error::Unauthorized); // identity mismatch
    }
    caller.require_auth(); // cryptographic proof
}

Burn as Revocation​

burn allows the admin to reduce a holder's balance, effectively revoking a credential. This is useful when a certification expires or a badge was issued in error. After burning, the holder's balance decreases and the total supply shrinks.

Security Considerations

  1. Admin is a single point of trust. The admin can mint to any address and burn from any address. For high-stakes deployments, use a multi-sig wallet or a governance contract as the admin to eliminate single-party control.

  2. No transfer path, full stop. Both transfer and transfer_from always fail with Error::TransferNotAllowed — they are not merely guarded by access control. There is no admin override, no escape hatch, and no indirect transfer route via allowances.

  3. Burn = revocation. The admin's ability to burn is equivalent to revoking a credential. Issuers should publish a clear off-chain revocation policy and consider emitting on-chain events (already implemented) to give holders visibility into revocation events.

  4. Re-initialization protection. The contract checks for an existing Admin key in storage and returns AlreadyInitialized if initialize is called more than once, preventing admin hijacking post-deployment.

  5. Storage bloat. Each unique holder creates a new persistent storage entry. For large-scale issuance, consider batching mints or using instance storage for high-frequency fields.

Deployment Guide

Build the Contract​

cd examples/soulbound-token
cargo build --target wasm32-unknown-unknown --release

The compiled WASM binary is at target/wasm32-unknown-unknown/release/soulbound_token.wasm.

Deploy to Testnet​

# 1. Generate or use an existing admin account
soroban keys generate badge-admin

# 2. Fund via Stellar Testnet Faucet
# https://laboratory.stellar.org/?network=testnet#account-creator

# 3. Deploy
soroban contract deploy \
  --wasm target/wasm32-unknown-unknown/release/soulbound_token.wasm \
  --network testnet \
  --source badge-admin
# Returns: CABC... (contract ID)

# 4. Initialize
soroban contract invoke \
  --id CABC... \
  --network testnet \
  --source badge-admin \
  -- initialize \
  --admin $(soroban keys address badge-admin) \
  --name "Soroban Contributor Badge" \
  --symbol SCB \
  --decimals 0

Mint a Badge​

soroban contract invoke \
  --id CABC... \
  --network testnet \
  --source badge-admin \
  -- mint \
  --admin $(soroban keys address badge-admin) \
  --to GBBD...recipient-address \
  --amount 1

Query Balance​

soroban contract invoke \
  --id CABC... \
  --network testnet \
  --source badge-admin \
  -- balance \
  --of GBBD...recipient-address

For more details, see the Deploy to Testnet guide.
