Oracle Consumer Pattern

The oracle consumer pattern enables smart contracts to read external data (price feeds, asset prices, etc.) from trusted oracle contracts through cross-contract invocation.

Overview​

An oracle consumer contract:

  • Reads data from an external oracle contract
  • Validates data freshness and accuracy
  • Uses prices for calculations (value estimation, collateral checks)
  • Handles oracle failures gracefully
  • Maintains configurable trust parameters

Use Cases​

  • DEX/AMM: Price feeds for token swaps and liquidity pools
  • Lending Protocols: Collateral valuation and liquidation pricing
  • Staking: Asset price feeds for reward calculations
  • Insurance: Event triggers based on oracle data
  • Derivatives: Price feeds for options and futures

Architecture​

┌─────────────────────────────┐
│  Oracle Consumer Contract   │
├─────────────────────────────┤
│ get_price(asset)            │
│ get_price_data(asset)       │
│ calculate_value(asset, amt) │
│ validate_freshness()        │
└──────────┬──────────────────┘
           │ Cross-Contract Call
           │
┌──────────▼──────────────────┐
│   Oracle Contract           │
├─────────────────────────────┤
│ price_feeds (persistent)    │
│ last_update (timestamp)     │
│ update_prices()             │
└─────────────────────────────┘

Data Flow​

  1. Query: Consumer asks oracle for price of asset
  2. Fetch: Oracle looks up price from data store
  3. Return: Oracle returns price with metadata (decimals, timestamp)
  4. Validate: Consumer checks freshness and accuracy
  5. Use: Consumer uses validated price for calculations

Trust Model​

Trust Assumptions​

  • Oracle Contract: Deployed by trusted party
  • Data Accuracy: Oracle is incentivized to provide accurate prices
  • Timeliness: Oracle updates prices regularly
  • Integrity: Oracle cannot be tampered with

Risk Mitigation​

  • Freshness Checks: Reject stale data beyond max_age
  • Price Bounds: Reject prices outside reasonable ranges
  • Multiple Oracles: Average prices from multiple sources
  • Circuit Breakers: Pause operations if prices are unusual

Implementation​

Unaudited Educational Example

This pattern and contract code are provided for educational purposes only. The code is unaudited and not intended for production use. Before deploying contracts handling real funds on mainnet, conduct thorough security reviews, write extensive tests, and obtain professional security audits.

Consumer Contract​

#[contract]
pub struct OracleConsumer;

#[contractimpl]
impl OracleConsumer {
    /// Initialize with oracle address and data freshness requirement
    pub fn init(env: Env, oracle_address: Address, max_age_secs: u64) {
        env.storage()
            .instance()
            .set(&symbol_short!("oracle"), &oracle_address);
        env.storage()
            .instance()
            .set(&symbol_short!("max_age"), &max_age_secs);
    }

    /// Fetch price from oracle with validation
    pub fn get_price(env: Env, asset: Symbol) -> Result<i128, OracleError> {
        let oracle = env.storage()
            .instance()
            .get(&symbol_short!("oracle"))
            .expect("Oracle not initialized");

        // Call oracle contract
        let price_data: Vec<i128> = env
            .invoke_contract(
                &oracle,
                &symbol_short!("get_price"),
                soroban_sdk::vec![&env, asset.into_val(&env)],
            )
            .map_err(|_| OracleError::InvalidOracle)?;

        // Validate response format
        if price_data.len() < 3 {
            return Err(OracleError::InvalidPrice);
        }

        let price = price_data.get_unchecked(0);
        let timestamp = price_data.get_unchecked(2) as u64;

        // Validate price is positive
        if price <= 0 {
            return Err(OracleError::InvalidPrice);
        }

        // Check data freshness
        let max_age = env.storage()
            .instance()
            .get(&symbol_short!("max_age"))
            .unwrap_or(3600);

        let current_time = env.ledger().timestamp();
        let age = current_time.checked_sub(timestamp)
            .ok_or(OracleError::StaleData)?;

        if age > max_age {
            return Err(OracleError::StaleData);
        }

        Ok(price)
    }

    /// Calculate value of amount based on oracle price
    pub fn calculate_value(
        env: Env,
        asset: Symbol,
        amount: i128,
    ) -> Result<i128, OracleError> {
        let (price, decimals, _) = self.get_price_data(env, asset)?;

        // value = (amount * price) / 10^decimals
        let value = amount
            .checked_mul(price)
            .ok_or(OracleError::InvalidPrice)?
            .checked_div(10_i128.pow(decimals))
            .ok_or(OracleError::InvalidPrice)?;

        Ok(value)
    }
}

Error Handling​

#[derive(Clone, Copy, PartialEq, Eq, Debug)]
#[repr(u32)]
pub enum OracleError {
    StaleData = 1,        // Data too old
    InvalidOracle = 2,    // Oracle call failed
    InvalidPrice = 3,     // Price is invalid
    Unauthorized = 4,     // Not authorized
}

Best Practices​

1. Data Freshness​

Always validate timestamp and reject stale data:

let max_age = 3600; // 1 hour
let age = current_time - timestamp;
if age > max_age {
    return Err(OracleError::StaleData);
}

2. Price Bounds​

Reject prices outside reasonable ranges:

// BTC price between $10k and $100k
if price < 10_000_000_000 || price > 100_000_000_000 {
    return Err(OracleError::InvalidPrice);
}

3. Multiple Sources​

Use multiple oracles to prevent single point of failure:

pub fn get_median_price(env: Env, asset: Symbol) -> Result<i128, OracleError> {
    let mut prices = Vec::new();
    
    for oracle_addr in self.get_oracles(&env)? {
        if let Ok(price) = self.fetch_from_oracle(&env, &oracle_addr, &asset) {
            prices.push(price);
        }
    }

    if prices.is_empty() {
        return Err(OracleError::InvalidOracle);
    }

    // Return median to handle outliers
    prices.sort();
    Ok(prices[prices.len() / 2])
}

4. Error Recovery​

Handle oracle failures gracefully:

pub fn get_price_or_cached(
    env: Env,
    asset: Symbol,
) -> Result<i128, OracleError> {
    // Try fresh price
    match self.get_price(&env, &asset) {
        Ok(price) => {
            // Cache for fallback
            self.cache_price(&env, &asset, price)?;
            Ok(price)
        }
        Err(_) => {
            // Fall back to cached price if oracle fails
            self.get_cached_price(&env, &asset)
        }
    }
}

5. Access Control​

Restrict configuration changes to authorized addresses:

pub fn set_oracle(env: Env, new_oracle: Address) {
    let admin: Address = env.storage()
        .instance()
        .get(&symbol_short!("admin"))
        .expect("Admin not set");

    require_auth(&admin);
    
    env.storage()
        .instance()
        .set(&symbol_short!("oracle"), &new_oracle);
}

Common Patterns​

Price Normalization​

Handle different decimal places:

pub fn normalize_price(price: i128, decimals: u32, target_decimals: u32) -> i128 {
    if decimals > target_decimals {
        price / 10_i128.pow(decimals - target_decimals)
    } else {
        price * 10_i128.pow(target_decimals - decimals)
    }
}

Value Calculation​

Calculate asset value from price and amount:

pub fn calculate_usd_value(
    price: i128,        // Price in USD
    decimals: u32,      // Price decimals
    amount: i128,       // Amount of asset
    amount_decimals: u32, // Asset decimals
) -> Result<i128, OracleError> {
    // Normalize to same decimal place
    let price_normalized = normalize_price(price, decimals, amount_decimals);
    
    // value = amount * price / 10^decimals
    let value = amount
        .checked_mul(price_normalized)
        .ok_or(OracleError::InvalidPrice)?
        .checked_div(10_i128.pow(amount_decimals))
        .ok_or(OracleError::InvalidPrice)?;

    Ok(value)
}

Circuit Breaker​

Pause operations if price changes dramatically:

pub fn check_circuit_breaker(
    env: Env,
    asset: Symbol,
    new_price: i128,
) -> Result<(), OracleError> {
    let old_price = self.get_cached_price(&env, &asset)?;
    
    // Allow max 20% price change
    let max_deviation = old_price / 5;
    let deviation = (new_price as i128 - old_price).abs();
    
    if deviation > max_deviation {
        return Err(OracleError::PriceDeviation);
    }
    
    Ok(())
}

Security Considerations​

Freshness Attacks​

Risk: Oracle goes offline, contract uses stale prices

Mitigation:

  • Set reasonable max_age (typically 1 hour)
  • Monitor oracle update frequency
  • Use circuit breakers for unusual price changes
  • Fall back to cached prices

Manipulation Attacks​

Risk: Oracle provides false prices

Mitigation:

  • Use multiple independent oracle sources
  • Verify oracle is properly incentivized/bonded
  • Implement price bounds checking
  • Monitor for suspicious patterns

Contract Injection​

Risk: Malicious oracle contract returns crafted data

Mitigation:

  • Whitelist oracle addresses
  • Validate response format and types
  • Use safe math (checked_mul, checked_div)
  • Test with multiple data scenarios

Denial of Service​

Risk: Oracle takes excessive gas or fails unexpectedly

Mitigation:

  • Set gas limits on oracle calls
  • Implement timeouts
  • Use try/catch for failure scenarios
  • Fall back to cached prices

Storage TTL and Data Expiry​

Risk: Storage entry expiration halting contract operations

The consumer contract relies on env.storage().instance() to persist the oracle contract address and max_age threshold. In Soroban, all ledger entries (including contract instance storage) have a Time-To-Live (TTL) and will eventually expire if not extended. If instance storage expires, calls to get_price or calculate_value will fail when trying to load uninitialized or expired keys.

Mitigation:

  • Extend instance TTL during initialization or key configuration updates (env.storage().instance().extend_ttl(...)).
  • Implement automated off-chain monitoring or bump operations using the Soroban CLI / SDK before TTL expiration occurs.

Reentrancy Considerations​

Risk: Cross-contract call reentrancy when querying oracle data

The contract executes cross-contract invocations (env.invoke_contract) to fetch price data from the configured external oracle contract.

In this specific implementation, get_price and get_price_data are read-only with respect to the consumer contract's internal state—they fetch external price vectors, validate timestamps, and return values without making prior or subsequent modifications to consumer storage. Because no state transitions occur around the cross-contract invocation in this example flow, classic reentrancy state manipulation does not directly affect this read-only pattern.

However, if you integrate this oracle consumer into a larger contract protocol (such as a lending market or DEX) where oracle price fetches trigger state updates, collateral adjustments, or asset transfers, you must follow the Checks-Effects-Interactions pattern or reentrancy guards to prevent untrusted external contracts from reentering state-modifying functions.

Limitations​

  • Trust Dependency: Consumer trusts oracle's data accuracy
  • Availability: Relies on oracle being online
  • Latency: Data is never completely real-time
  • Cost: Oracle calls consume gas
  • Manipulation: Oracles can be attacked or compromised
  • Storage TTL Expiry: Instance storage entries expire if not maintained via TTL extension calls
  • Reentrancy Context: While the read-only oracle fetch is non-state-modifying, integrating callers must handle cross-contract interaction ordering safely
