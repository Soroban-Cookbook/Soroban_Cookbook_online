Overview​

This page demonstrates the pattern detail template: metadata header, prerequisite and security sections, tabbed code, and related patterns. Use it as a starting point when adding new contract patterns to the cookbook.

The snippets below match examples/hello-world/src/lib.rs. HelloWorld reads and writes instance storage key "msg" via hello() and set_message(). There is no hello(to: String) entry point.

Prerequisites

  • Rust stable and cargo (setup guide)
  • Stellar CLI installed (stellar --version) — see Building and Compilation
  • wasm32-unknown-unknown target (rustup target list --installed)
  • Basic familiarity with Rust modules and soroban_sdk types

Implementation

Read instance storage and return a greeting string. This is the smallest useful contract for bootstrapping tests and deployments. Canonical source: examples/hello-world/src/lib.rs (tests are in the same file under #[cfg(test)], not a separate src/test.rs).

Learner Safety & Production Warning

The example contract code on this page is unaudited and provided strictly for educational and pattern template purposes. Do not use this material in production without independent security audits and complete test coverage.

When to use

Use this pattern to verify tooling, ledger integration, and storage before layering tokens or authorization.

Limits & Constraints

  • Re-entrancy: Does not perform external contract calls or token transfers, so cross-contract re-entrancy attack vectors do not apply to this minimal contract.
  • Storage TTL & Data Expiry: Uses instance storage (env.storage().instance()), which shares the contract instance's lifecycle and TTL. Instance storage entries will expire if the contract instance TTL passes without being extended via extend_ttl. Production contracts should manage TTL extensions explicitly or use persistent storage with appropriate archival management.

Run the crate tests:

cd examples/hello-world
cargo test

Both test_default_greeting and test_custom_greeting should pass. Build with stellar contract build --package hello-world from examples/ (see Building and Compilation).

Security considerations

  • Storage scope: Instance storage is shared across all invocations; never store per-user secrets without namespacing by Address.
  • Upgrade surface: If you add admin functions later, protect them with require_auth and explicit roles.
  • Re-entrancy: Not applicable to this minimal example; review when adding cross-contract calls.

Production checklist

Before mainnet, add thorough tests, metering review, and an explicit data migration plan if storage layout changes.
