Security Vulnerability

Real-World Documentation Examples​

About Storage Types

Soroban provides three types of storage: - Temporary: Deleted after a short period, cheapest option - Persistent: Remains until explicitly deleted, moderate cost - Instance: Tied to contract instance lifetime, balanced cost Choose the appropriate type based on your data lifecycle requirements.

Gas Optimization Strategy

To minimize gas costs in your Soroban contracts: 1. Use Temporary storage for ephemeral data 2. Batch operations when possible to reduce transaction overhead 3. Implement early returns to avoid unnecessary computation 4. Cache frequently accessed values in local variables 5. Use efficient data structures (e.g., Map over Vec for lookups)

Common Pitfall

When working with timestamps in Soroban, remember that env.ledger().timestamp() returns the ledger close time, not the current wall clock time. This value only updates when a new ledger is closed (approximately every 5 seconds).

Anti-Pattern: Unbounded Loops

Avoid unbounded loops in your contract code:

// ❌ BAD: Unbounded loop
while condition {
    // This could run forever and exceed gas limits
}

// ✅ GOOD: Bounded iteration
for i in 0..MAX_ITERATIONS {
    if !condition { break; }
    // Safe iteration with upper bound
}

Always set explicit limits to prevent gas exhaustion and ensure contract reliability.

Best Practice: Input Validation

Always validate input parameters at the beginning of your contract functions:

pub fn transfer(env: Env, from: Address, to: Address, amount: i128) {
    // ✅ Validate inputs first
    from.require_auth();
    
    if amount <= 0 {
        panic!("Amount must be positive");
    }
    
    if from == to {
        panic!("Cannot transfer to self");
    }
    
    // Now proceed with business logic
    // ...
}

This pattern provides clear error messages and prevents wasted computation on invalid inputs.
